# CampusHub API 测试（Apifox）

## 文件

- `campushub-apifox.postman_collection.json`：全量集合（96 请求 / 117 断言），Postman Collection v2.1，Apifox 可直接导入。
- `campushub-apifox.environment.json`：本地环境变量（`baseUrl`、演示账号）。
- `build-collection.mjs`：集合生成脚本（改完用例后执行 `node build-collection.mjs` 重新生成 JSON）。
- `tiny.png`：图片上传用例使用的 1×1 PNG。

## 导入与执行

1. 启动后端：`cd backend && mvn spring-boot:run`（http://localhost:8080）。
2. 重置演示数据（建议每次执行前）：`db\init-db.bat`。
3. 打开 Apifox → 导入项目 → 选择 Postman，导入 `campushub-apifox.postman_collection.json`。
4. 导入 `campushub-apifox.environment.json` 作为环境，选择该环境。
5. 按目录顺序执行 `00 认证` → `01 商品` → … → `07 管理端与权限`；每个请求自带断言，结果在「测试」页签查看。
6. **一次跑完全部 96 个接口**：左侧进入「自动化测试」→「场景用例」→ 新建 → 添加步骤 → 从接口导入 → 勾选整个集合（96 个）→ 选择环境 → 运行。当前 Apifox 中已创建场景「CampusHub 全量回归」。

> 集合会创建测试用户、商品、出价、交易单、评价、举报与私聊记录。重复执行前请运行 `db\init-db.bat`；商品 id、交易单 id 等变量由脚本自动写入。

### Apifox 场景说明

场景「CampusHub 全量回归」共 96 步，其中 **93 步启用并全部通过**。以下 3 步在场景中单独禁用，请求仍保留在集合里：

| 步骤 | 原因 | 替代覆盖 |
| :--- | :--- | :--- |
| 图片上传（手动，需文件） | Apifox 场景不会自动绑定本地文件，会以空文件请求返回 500；手动执行时选择 `tiny.png` 即可 | Newman 跑全量集合时该步骤通过；发布接口另一端到端覆盖图片校验 |
| 匿名留言 401 | Apifox 将 HTTP 401 直接判为步骤失败，断言无法改变判定 | Newman 全量集合中通过；后端 `AuthInterceptorTest` 覆盖 401 |
| 未登录访问受保护接口 | 同上 | 同上 |

## 与自动化脚本的关系

`tests/api-e2e.ps1` 是同一批接口断言的命令行版本，可在 CI 中执行；Apifox 全量集合用于可视化回归与接口调试，Newman 可无头执行同一份 JSON（96 请求 / 117 断言全部通过）。
