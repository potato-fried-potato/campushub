### 一、项目愿景与背景 (Vision & Background)

校园闲置物品（如二手教材、数码外设、代步自行车、宿舍生活小电器）流转频繁。由于缺乏可信度高、校区明确的专门交易工具，学生多依赖杂乱的微信朋友圈或匿名表白墙，存在信息查找难、缺乏成色与分类筛选、沟通链路断裂等痛点。

**智校互联 (CampusHub)** 旨在打造一个专属于大学校园的真实、轻量、高可用的二手闲置物品协同交易平台。平台坚持**极简与健壮架构**（Spring Boot 3 + Vue 3 + MySQL 8.0 原生体系），彻底摒弃对繁重第三方中间件的强依赖，为校园师生提供开箱即用的闲置发布、即时检索、议价撮合与信用交易能力。

---

### 二、目标用户画像 (User Personas)

1. **买家同学 (Buyer)**：想以低成本淘到高年级正版课本、品质良好的数码外设或代步车辆，要求能按校区、成色清晰筛选，支持在线砍价（出价不得低于挂牌价的 8 折）与**站内沟通**（商品问答或交易单私聊），平台不公开卖家手机号。
2. **卖家同学 (Seller)**：毕业离校或宿舍整理产生闲置，希望在 1 分钟内拍照上传、标注价格和成色并挂网出售，能随时下架、重新上架或标记线下已售。
3. **系统管理员 (Admin)**：通过**与用户端分开的管理端**对全校交易动态进行宏观监管，查阅运行数据、管理用户与商品、处置举报；管理员账号**不参与用户侧交易活动**（不发布、不出价、不预约、不留言、不评价、不举报）。

### 四、核心用户故事验收标准 (Acceptance Criteria, AC)

> 本节覆盖全部 12 个用户故事（US-01~12）；每条 AC 将在开发阶段与代码实现及自动化测试一一对应，测试用例与执行方式详见 `docs/06` 测试用例与执行规范。

#### 【US-01】学号注册与登录（JWT 鉴权）
* **AC-1.1**：学号与密码匹配时返回标准 JWT Token 及昵称/学号/角色信息；密码错误返回业务码 `4002`（学号或密码错误）；
* **AC-1.2**：密码使用 BCrypt 单向哈希存储，数据库中不存在明文；重复学号注册被拦截；
* **AC-1.3**：未登录调用受保护接口（发布、砍价、我的发布）返回 HTTP 401；
* **AC-1.4**：注册成功自动生成内联 SVG 头像（Base64 Data URI），不依赖任何外部图床。

#### 【US-02】集市多维检索
* **AC-2.1**：默认返回 `ON_SALE`（在售）商品并按发布时间倒序；支持切换查看 `SOLD`（已售）；
* **AC-2.2**：提供 6 大分类（教材图书 / 数码 3C / 代步运动 / 生活日用 / 服饰鞋包 / 乐器兴趣），点击即时无刷新筛选，分类标签展示在售数量；
* **AC-2.3**：成色（全新~8 成新）与校区（东风校区/科学校区）联动筛选，关键词模糊匹配标题与描述；
* **AC-2.4**：支持四种排序：最新发布 / 价格最低 / 价格最高 / 最多浏览；
* **AC-2.5**：**登录后列表自动排除自己发布的商品**（自己的商品在「我的发布」中管理），匿名浏览不受影响。

#### 【US-03】商品详情与卖家联系
* **AC-3.1**：独立路由详情页 `/#/item/:id`，支持多图切换画廊；
* **AC-3.2**：展示挂牌价、原价对比，并计算「立省金额（折扣）」；
* **AC-3.3**：卖家名片只展示昵称、脱敏学号认证标识、信用分与评价入口，**不公开卖家手机号**（手机号仅管理员后台可见）；「联系卖家」一律走站内：未成交时定位到公开的商品问答输入框，已生成交易单时打开交易单私密会话；
* **AC-3.4**：每次访问详情页浏览量 +1；
* **AC-3.5**：详情页展示交易安全提示（校内当面交易、防止转账诈骗）。

#### 【US-04】闲置发布与图片直存
* **AC-4.1**：发布表单强制校验标题、分类、价格与实物照片；
* **AC-4.2**：图片经 `/api/files/upload` 上传，服务端校验文件头魔数，仅允许 JPG/PNG/WEBP/GIF，伪装文件被拒绝；
* **AC-4.3**：图片转 Base64 Data URI 直存 MySQL（`item_image.image_data`），零文件系统依赖，单张 ≤ 5MB；
* **AC-4.4**：未登录调用上传接口返回 HTTP 401；
* **AC-4.5**：发布成功后自动跳转该商品详情页。

#### 【US-05】我的发布与状态流转
* **AC-5.1**：`GET /api/items/mine` 仅返回当前登录用户发布的商品；
* **AC-5.2**：支持 `ON_SALE → OFF_SHELF / SOLD` 与 `OFF_SHELF → ON_SALE` 状态流转，仅商品发布者本人可操作，越权返回业务码 `4003`；管理员不通过该接口操作商品（违规商品强制下架走 `/api/admin/items/{id}/off-shelf`）；存在 `PENDING` 交易单时禁止手动改状态，需先完成或取消交易单；
* **AC-5.3**：下架商品不再出现在集市在售列表，重新上架后恢复展示；
* **AC-5.4**：交易单 `COMPLETED` 时商品自动置为 `SOLD` 并写入成交快照（与 US-06、US-10 联动）；卖家手动「线下已售」不产生交易单与成交快照、双方不可评价（AC-11.6）。

#### 【US-06】砍价议价闭环
* **AC-6.1**：出价必须**低于当前挂牌价**且**不得低于挂牌价的 80%（8 折）**，防止恶意压价；不能对自己的商品出价；详情页出价弹窗展示可出价区间与 9 / 8.5 / 8 折快捷出价，后端同样校验该下限；
* **AC-6.2**：同一买家对同一商品不能重复存在待处理出价（`PENDING`）；
* **AC-6.3**：卖家可「接受/拒绝」，买家可「取消」；角色不符或商品非在售状态被拒绝；
* **AC-6.4**：卖家接受出价后**生成交易单**（来源 `BARGAIN`、成交价 = 出价）：出价置为 `ACCEPTED`，同商品其他待处理出价自动置为 `REJECTED`，进行中的预约自动置为 `CLOSED`，商品进入「待成交」锁定；
* **AC-6.5**：已处理（非 PENDING）的砍价记录不可重复操作；
* **AC-6.6**：「交易中心」提供双视角（我收到的 / 我发出的）与待处理数量角标，支持留言出价；
* **AC-6.7**：商品处于「待成交」锁定期时，不再接受任何新的出价。

#### 【US-07】一键启动脚本
* **AC-7.1**：`一键启动.bat` 六步自检：JDK 21 → MySQL80 服务 → 数据库结构（**首次自动导入 init.sql**）→ 前端产物（源码变更自动 `npm run build`）→ 后端产物（自动 `mvn package`）→ 启动并自动打开浏览器；
* **AC-7.2**：`一键停止.bat` 释放 8080 端口并关闭后端进程；
* **AC-7.3**：`db\init-db.bat` 一键重建演示数据（14 用户 / 6 分类 / 32 商品 / 45 图 / 5 条砍价 / 1 张已完成交易单 / 3 条交易单私聊）；

#### 【US-08】平台数据看板
* **AC-8.1**：`/api/system/stats` 返回在售数、成交数、认证用户数、累计浏览量；
* **AC-8.2**：首页看板实时展示四项指标；分类标签同步展示各分类在售数量。

#### 【US-09】站内求购与留言互动
* **AC-9.1**：登录用户可在商品详情页对商品发表留言提问；未登录调用留言接口返回 HTTP 401；
* **AC-9.2**：留言内容必填且限制 1~200 字，空白或超长内容被拦截；
* **AC-9.3**：商品发布者可在留言下回复，同一话题按时间顺序展示买家提问与卖家回复，含双方昵称与时间；
* **AC-9.4**：留言与回复持久化存储，刷新或重新进入详情页后沟通记录完整可见；
* **AC-9.5**：卖家侧展示待回复留言数量提醒，买家侧标记卖家新回复。

> **留言定位**：US-09 的商品问答是**公开留言板**——任何访客（含其他买家）都能看到商品下的全部话题与回复，用于商品本身的提问（成色、配件、是否还在等）。交易谈成后的面交时间、地点等细节属于交易双方私事，走 US-10 的**交易单私密会话**（`deal_message`），两套数据不共用、不互相展示。

#### 【US-10】交易单与线下交易预约
* **AC-10.1**：买家可按挂牌价「立即购买」，也可提交「预约购买」（意向预约单，含期望面交时间与备注）——预约是**按挂牌价购买的意向**，提交时不锁定商品，卖家确认后即按挂牌价生成交易单并锁定商品（等价于「立即购买 + 约定见面时间」）；不能对自己发布的商品购买或预约；
* **AC-10.2**：同一买家对同一商品只能存在一个进行中的预约单（`PENDING` / `CONFIRMED`），重复提交被拦截；
* **AC-10.3**：三条成交路径都会生成**交易单** ——「立即购买」生成来源 `DIRECT`（成交价 = 挂牌价）的交易单，「卖家接受出价」生成来源 `BARGAIN`（成交价 = 出价）的交易单，「卖家确认预约」生成来源 `RESERVATION`（成交价 = 挂牌价）的交易单；生成即锁定商品为「待成交」，集市与详情页标记该商品已被预约/待成交；
* **AC-10.4**：商品处于「待成交」锁定期时，其他买家不可再立即购买、不可出价、不可提交预约；
* **AC-10.5**：交易单待成交期间，买卖任一方均可取消；取消后交易单置为 `CANCELLED`，商品回到「在售」，来源为预约时该预约置为 `CLOSED`；
* **AC-10.6**：面交完成后，买卖任一方可确认完成；交易单置为 `COMPLETED`，商品置为 `SOLD`，成交买家与成交价写入商品成交快照；
* **AC-10.7**：交易单完成后，同商品其他进行中预约自动关闭；预约状态流转（待确认 → 已确认 / 已拒绝 / 已取消 / 已关闭）全程留痕；
* **AC-10.8**：买家侧「我的购买」集中展示自己的交易单（待成交 / 已完成 / 已取消）以及在谈的出价与预约，支持按状态筛选、查看累计支出；交易双方可通过**交易单私密会话**（`deal_message`，仅该单的买家与卖家可读写）约定面交时间与地点，未读消息计入顶部待办角标，交易单取消后会话转只读；该私聊与**公开的商品问答**（`item_message`，任何访客可见）是两套独立数据，不可混用。

> **交易单状态机**：`PENDING`（待成交，锁定商品）→ `COMPLETED`（已完成，商品 `SOLD`）或 `CANCELLED`（已取消，商品回 `ON_SALE`）。同一商品同时最多存在一张 `PENDING` 交易单。

#### 【US-11】信用评价与举报风控
* **AC-11.1**：交易单 `COMPLETED` 后，交易双方可对对方提交 1~5 星信用评价与文字评价；
* **AC-11.2**：同一交易单中一方对另一方仅能评价一次，非该交易单的买卖双方调用评价接口被拒绝；
* **AC-11.3**：登录用户可对非自己发布的商品提交举报（举报原因 + 补充说明），同一用户对同一商品仅能举报一次；
* **AC-11.4**：卖家名片与个人页展示聚合信用信息（平均星级与评价条数），信用分 = 基础 80 分 + Σ(星级 − 3) × 5，限 0~100；
* **AC-11.5**：举报记录进入管理后台待处理列表，管理员处置（下架商品 / 驳回举报）后商品状态同步更新（与 US-12 联动）；
* **AC-11.6**：卖家「线下已售」的商品不产生交易单、无成交对手方，因此不可评价（页面需明示）。

#### 【US-12】管理后台
* **AC-12.1**：管理端与用户端分开——管理端有独立登录页 `/#/admin/login`（只接受角色 `ADMIN` 的账号，学生账号登录被拒并提示），拥有独立布局与侧边栏，用户端不出现管理入口；未登录或非管理员访问 `/admin/**` 一律跳回该登录页；**管理员账号不参与用户侧活动**：仅可只读浏览集市与调用 `/api/admin/**`，发布 / 出价 / 预约 / 留言 / 评价 / 举报 / 交易单操作等写接口一律返回 `4003`，用户端也不显示这些操作入口；普通用户调用管理接口返回业务码 `4003`，未登录返回 HTTP 401；
* **AC-12.2**：用户管理：管理员可查看用户列表并禁用/启用账号，被禁用账号无法登录；
* **AC-12.3**：商品管理：管理员可查看全部商品（含下架/已售）并对违规商品执行强制下架，强制下架商品不再出现在集市；
* **AC-12.4**：举报处置：管理员可处理 US-11 的举报事项（下架商品或驳回举报），处置动作全程留痕；
* **AC-12.5**：管理后台首页展示平台统计数据（在售 / 成交 / 认证用户 / 累计浏览），复用 `/api/system/stats`。

### 五、非功能性需求规范 (NFRs)

1. **零外部中间件强依赖**：Spring Boot 3 + 本地 MySQL 8.0 原生存储，不要求安装 Redis、RabbitMQ、MinIO 等外部中间件；
2. **图片零文件系统依赖**：商品图片与头像均以 Base64 Data URI 持久化于 MySQL，数据库一键导入即完整还原演示环境；
3. **前后端工程化解耦**：前端 Vite + Vue Router 组件化工程，构建产物由 Spring Boot 统一托管；接口遵循 RESTful 契约（`docs/02`）；
4. **极简运维**：Windows CMD 批处理一键启停/自动建库；Git 全量版本管理（Conventional Commits）；
5. **质量门禁**：JUnit 冒烟测试 + 接口端到端回归脚本（`tests/api-e2e.ps1`），覆盖全部接口类 AC 断言，脚本自动还原测试数据；测试用例清单与执行规范见 `docs/06`。
