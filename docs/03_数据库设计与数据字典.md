# 智校互联 (CampusHub) 校园二手交易协同平台
## 03. 数据库设计与数据字典规范

> **课程班级**：软件工程 2402 · 第 11 组  
> **制定人员**：边皓东（组长）  
> **生效版本**：v1.1.0（与 01 需求基线 v1.7.0、02 API 契约 v1.1.0 配套，新增 `deal` 表与商品成交快照字段）

### 一、设计原则

1. **极简原生**：MySQL 8.0 + InnoDB，字符集统一 `utf8mb4`，不引入缓存、消息队列等外部中间件；
2. **图片零文件系统依赖**：商品图片与头像以 Base64 Data URI 直存 `LONGTEXT`（AC-4.3），数据库一键导入即可完整还原演示环境；
3. **主键与时间**：主键统一 `BIGINT` 自增；时间统一 `DATETIME`，创建时间默认 `CURRENT_TIMESTAMP`，更新时间 `ON UPDATE` 自动维护；
4. **状态机清晰**：状态字段使用英文枚举（见 02 文档字典），商品状态机全部通过 `item.status` 表达，不物理删除数据；
5. **参照完整性**：外键显式声明；重复操作拦截优先使用唯一索引兜底（评价、举报），业务状态校验在服务层完成。

### 二、E-R 关系总览

```mermaid
erDiagram
    user ||--o{ item : "发布"
    category ||--o{ item : "归类"
    item ||--o{ item_image : "包含多图"
    user ||--o{ bargain : "买家出价"
    item ||--o{ bargain : "被砍价"
    user ||--o{ item_message : "发送"
    item ||--o{ item_message : "留言"
    user ||--o{ reservation : "发起预约"
    item ||--o{ reservation : "被预约"
    user ||--o{ deal : "买入 / 售出"
    item ||--o{ deal : "成交"
    deal ||--o{ deal_message : "私密会话"
    user ||--o{ deal_message : "发送"
    user ||--o{ review : "评价 / 被评价"
    item ||--o{ review : "被评价"
    user ||--o{ report : "举报"
    item ||--o{ report : "被举报"
```

核心关系说明：

1. 用户（`user`）是唯一的参与主体：既可以是买家（出价、预约、留言、评价、举报），也可以是卖家（发布商品、处理出价与预约），管理员只是 `role = ADMIN` 的用户；
2. 商品（`item`）属于一个分类与一个卖家，包含多张图片（`item_image`）；
3. 砍价（`bargain`）与预约（`reservation`）都是「买家 × 商品」的交易意向记录，状态流转驱动商品状态联动；
4. 交易单（`deal`）是三条成交路径（立即购买 / 砍价接受 / 预约确认）的统一落点：`PENDING` 锁定商品、`COMPLETED` 写入商品成交快照、`CANCELLED` 解锁；
5. 「待成交」不新增商品状态值，由 `deal` 中 `PENDING` 记录派生（见 4.11 节），保证 `item.status` 状态机与 AC-5.2 完全一致；
6. 交易单私密会话（`deal_message`）挂在交易单上而非商品上：它是买卖双方的约见私聊，公开的商品问答仍走 `item_message`（见 4.12 节）。

#### 4.7 reservation 意向预约表

| 字段 | 类型 | 约束 | 说明 |
| :--- | :--- | :--- | :--- |
| id | BIGINT | PK，自增 | 主键 |
| item_id | BIGINT | NOT NULL，FK → item.id | 目标商品 |
| buyer_id | BIGINT | NOT NULL，FK → user.id | 预约买家 |
| expect_time | DATETIME | NULL | 期望交易时间 |
| remark | VARCHAR(200) | NULL | 备注（如交易地点意向） |
| status | VARCHAR(16) | NOT NULL，默认 `PENDING` | `PENDING` / `CONFIRMED` / `REJECTED` / `CANCELLED` / `CLOSED` |
| created_at | DATETIME | NOT NULL，默认当前时间 | 提交时间 |
| handled_at | DATETIME | NULL | 处理时间 |

索引：`idx_item_status (item_id, status)`、`idx_buyer (buyer_id, created_at)`。

设计说明：

1. **商品锁定为派生状态**：锁定不再由预约派生——`deal` 表存在 `PENDING` 交易单时，商品在集市与详情接口返回 `reserved = true`，不新增 `item.status` 取值，保持商品状态机三态不变（AC-5.2、AC-10.3）；
2. 进行中预约定义为 `PENDING` / `CONFIRMED`，同一 `(item_id, buyer_id)` 至多一条进行中记录（服务层保证，AC-10.2）；
3. 商品进入 `SOLD`（交易单确认成交或卖家线下已售）时，进行中预约同事务置为 `CLOSED`（AC-10.5、AC-10.7）。

#### 4.10 信用分计算口径（不落库，实时汇总）

信用分由 `review` 表实时汇总得出，供信用中心与商品详情页卖家卡片展示：

```
creditScore = clamp(80 + Σ(rating - 3) × 5, 0, 100)
```

| 项 | 说明 |
| :--- | :--- |
| 基础分 | 80 分，每个认证用户起点一致 |
| 单条评价影响 | 5 星 +10 / 4 星 +5 / 3 星 0 / 2 星 -5 / 1 星 -10 |
| 取值区间 | 下限 0 分，上限 100 分 |
| 信用等级 | ≥ 90 优秀；≥ 75 良好；≥ 60 一般；< 60 较低 |

接口同时返回 `baseScore`、`ratingDelta`（星级增量之和）、`avgRating` 与 `reviewCount`，便于前端展示分项来源；实现见 `ReviewService.listByUser`。

| 字段 | 类型 | 约束 | 说明 |
| :--- | :--- | :--- | :--- |
| id | BIGINT | PK，自增 | 主键 |
| deal_id | BIGINT | NOT NULL，FK → deal.id | 所属交易单 |
| sender_id | BIGINT | NOT NULL，FK → user.id | 发送者 |

| is_read | TINYINT(1) | NOT NULL，默认 0 | 接收方是否已读 |

### 五、索引策略

| 查询场景 | 使用索引 | 说明 |
| :--- | :--- | :--- |
| 集市列表（状态 + 分类 + 时间倒序） | `item.idx_status_category` + `idx_created` | 覆盖主查询路径（AC-2.1 / 2.2） |
| 卖家「我的发布」 | `item.idx_seller` | 按卖家 + 状态过滤（AC-5.1） |
| 校区 / 成色筛选 | `item.idx_campus` / `idx_condition` | 联合筛选时由优化器选择 |
| 关键词模糊匹配 | 暂不建索引 | 演示数据规模（32 商品）下 `LIKE '%kw%'` 可接受；如需扩展可启用 MySQL 8 全文索引：`FULLTEXT(title, description) WITH PARSER ngram` |
| 砍价进行中校验 / 列表 | `bargain.idx_item_status`、`idx_buyer` | AC-6.2 / 6.6 |
| 预约进行中校验 / 锁定判定 | `reservation.idx_item_status` | AC-10.2 / 10.3 |
| 留言未读提醒 | `item_message.idx_receiver_read` | AC-9.5 |
| 防重复评价 / 举报 | `review.uk_item_reviewer`、`report.uk_item_reporter` | 唯一索引兜底，冲突返回 4005 |
| 后台举报队列 | `report.idx_status` | 按状态 + 时间处理（AC-12.4） |
| 商品待成交锁定判定 | `deal.uk_deal_active_item`、`item.idx_status_category` | 唯一索引保证同商品最多一张 `PENDING` 交易单，冲突返回 4005（AC-10.3 / 10.4） |
| 我的交易单（双视角） | `deal.idx_buyer`、`deal.idx_seller` | 买家 / 卖家视角 + 状态过滤（AC-10.5 / 10.6） |
| 成交评价资格 | `deal.idx_item (item_id, created_at)` | 按商品取最近一张 `COMPLETED` 交易单判定对手方（AC-11.1） |
| 交易单私密会话 | `deal_message.idx_deal`、`idx_receiver_unread` | 按交易单拉取会话 + 未读角标统计（AC-10.8） |

### 六、MySQL 8.0 DDL 建表脚本

> 以下脚本与 `db/init.sql` 一致，由 `db/init-db.bat` 一键重建（AC-7.3）。

```sql
-- 演示环境重建脚本：先删库再建库，请勿在生产环境执行
DROP DATABASE IF EXISTS campushub;
CREATE DATABASE campushub
  DEFAULT CHARACTER SET utf8mb4
  DEFAULT COLLATE utf8mb4_0900_ai_ci;
USE campushub;

-- 1. 用户表
CREATE TABLE `user` (
  `id`         BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键',
  `student_no` VARCHAR(20)  NOT NULL COMMENT '登录账号（学号；管理员为 admin）',
  `password`   VARCHAR(100) NOT NULL COMMENT 'BCrypt 哈希密码',
  `nickname`   VARCHAR(16)  NOT NULL COMMENT '昵称',
  `phone`      VARCHAR(20)  NOT NULL COMMENT '联系电话',
```

### 八、关键事务与数据一致性

| 业务场景 | 事务内操作 | 关联 AC |
| :--- | :--- | :--- |
| 接受出价 | 出价 → `ACCEPTED`；生成 `PENDING` 交易单（`source = BARGAIN`、`dealPrice = offerPrice`）；同商品其它 `PENDING` 出价 → `REJECTED`；进行中预约 → `CLOSED`；商品锁定为「待成交」 | AC-6.4 |
| 立即购买 | 生成 `PENDING` 交易单（`source = DIRECT`、`dealPrice = 挂牌价`）；其它 `PENDING` 出价 → `REJECTED`；进行中预约 → `CLOSED`；商品锁定为「待成交」 | AC-10.1、AC-10.3 |
| 预约确认 | 预约 → `CONFIRMED`；生成 `PENDING` 交易单（`source = RESERVATION`、`dealPrice = 挂牌价`）并锁定商品（`reserved = true`） | AC-10.3 |
| 确认成交 | 交易单 → `COMPLETED`；商品 → `SOLD` 并写入成交快照 `sold_buyer_id` / `sold_price` / `sold_at`；进行中预约 → `CLOSED` | AC-10.6、AC-10.7 |
| 取消交易单 | 交易单 → `CANCELLED`；商品解锁回到 `ON_SALE`；来源为预约时该预约 → `CLOSED` | AC-10.5 |
| 商品售出（线下） | 商品 → `SOLD`，无交易单与成交快照；进行中预约（`PENDING` / `CONFIRMED`）→ `CLOSED` | AC-5.4、AC-10.7 |
| 预约拒绝 / 取消 | 预约 → `REJECTED` / `CANCELLED` | AC-10.4 |
| 举报处置 | 举报 → `OFF_SHELF` / `REJECTED`；`OFF_SHELF` 时商品强制下架；记录 `handled_by` / `handled_at` | AC-11.5、AC-12.4 |
| 账号禁用 | 用户 → `DISABLED`；登录接口拦截（4007） | AC-12.2 |
| 详情页浏览 | 商品 `view_count + 1` | AC-3.4 |
| 留言已读 | 接收者读取后 `is_read = 1`，驱动未读角标 | AC-9.5 |
| 交易单私聊已读 | 接收者读取后 `deal_message.is_read = 1`，驱动顶部待办角标 | AC-10.8 |
